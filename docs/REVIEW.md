# Разбор версии 1.86.0

Статический анализ распакованной обработки. Ниже указаны наблюдения по коду и способы проверить последствия на тестовых данных.

| Участок | Наблюдение | Проверка или изменение |
|---|---|---|
| [Остатки, два режима](../src/Module.bsl#L6411-L6450) | Полное обновление и каталог могут записать сумму всех складов на 106 после раздельной передачи. Если положительные количества других складов сохранились и КИТ суммирует их, доступность может быть завышена | На одном варианте с остатками на двух складах сравнить все девять значений после каждой кнопки. До перевода на регламент определить один режим источника остатков |
| [Постраничное чтение заказов](../src/Module.bsl#L5328-L5379) | При размере страницы 25 счётчик порога удваивается. При 100 заказах алгоритм завершится после третьей страницы, прочитав 75 | Добавлять фактически прочитанное количество. Проверить 25, 26, 75, 76 и 100 заказов, ошибку на промежуточной странице |
| [Сообщение о подтверждении](../src/Module.bsl#L5935-L5955) | После создания заказа пишется «Подтвердили заказ», при этом вызов подтверждения закомментирован | Выводить подтверждение только после успешного ответа КИТ |
| [Настройки заказов](../src/Module.bsl#L7310-L7333) | Предупреждение о Garage Sale допускает продолжение после «Да» для текущего выбранного узла | Привязать доступность команды к настроенному кабинету; протестировать отдельный маршрут основного магазина |
| [Полная выгрузка остатков](../src/Module.bsl#L591-L623) | При пустой исходной таблице процедура завершается до сверки проданных вариантов. После непустой отправки факт успешного применения всех пакетов не передаётся в вызывающую процедуру как условие запуска сверки | Разделить пустую выборку, сбой получения данных и подтверждённый нулевой остаток. Смоделировать отклонение второго пакета |
| [Задержки при ошибках сети](../src/Module.bsl#L442-L461) | Пауза реализована циклом ожидания. Во время длинной задержки рабочий процесс остаётся занят | Замерить нагрузку при 429 и временной недоступности, для фонового сценария переносить повтор на следующую попытку |
| [Настройки узла](../src/Module.bsl#L6339-L6381) | Наличие свойства «СкладСкидок» также выбирает логику основного сайта в каталоге и других процедурах. Удаление настройки скидок может изменить несколько операций | Ввести явный признак сценария сайта, покрыть оба кабинета |
| [Раздельная отправка](../src/Module.bsl#L6701-L6800) | Между расчётом разницы и подтверждением пользователем остаток может измениться. Повторное чтение проверяет принятый пакет, но не обновляет исходный расчёт 1С | Для фонового режима заново считать доступность перед отправкой или использовать очередь изменений |
| [Получение KIT ID](../src/Module.bsl#L6786-L7067) | Проверяются штрихкод, соответствие одной характеристике, UUID, свойство 00000000230, конфликт значения и сохранность имени. Режим блокировок определяется по строковому представлению метаданных | В рабочем типе базы проверить первую запись, повтор, чужой ID, одновременную запись из двух сеансов и отмену. Проверить повторным открытием карточки |
| [Ключи доступа](../src/Module.bsl#L5024-L5029) | В рабочей EPF три ключа представлены литералами. Обладатель файла может их извлечь | Перенести ключи в защищённые настройки окружения. До переноса проверять полный diff экспорта |

В 1.85.1 для команды получения KIT ID проверены структура собранной EPF и совпадение повторно извлечённых исходников. Проверка в сеансе 1С ожидается. Контрольный сценарий: ввести 2700011149511, сверить ID с КИТ и имя ONE SIZE, WHITE; повторить вместе с отсутствующим ШК; проверить одинаковый итог при повторном запуске и отказ от полной обработки при отмене.

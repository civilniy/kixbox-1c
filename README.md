# Обмен KIXBOX между 1С и Яндекс КИТ

Техническая база версии **1.84.4**. Модуль формы внешней обработки содержит 7 178 строк и 161 процедуру и функцию. Одна форма обслуживает два кабинета, основной магазин и Garage Sale. Настройки узла выбираются до вызова бизнес-операции. Проверяйте ветку выбранного сайта при анализе любого обработчика.

## Идентификаторы и остатки

Код справочника склада 1С выбирает локальную ссылку. Публичный API принимает внутренний UUID склада КИТ в поле `warehouse_id`. B2B использует внешний идентификатор склада из 1С и дополнительно сверяет привязку с внутренним ID КИТ. Полная таблица девяти соответствий находится в [настройках узла](src/Module.bsl#L6357-L6365).

Кнопка «Товар по складам» рассчитывает доступный остаток для каждой пары «вариант × склад» как максимум из нуля и физического остатка за вычетом неотрицательного резерва. Сравнивает результат с текущим количеством в КИТ перед записью. При обычной выгрузке каталога и полном обновлении остатков основной сайт использует сводный режим. Одновременное применение обоих режимов к одним товарам требует отдельного решения по учёту остатков.

Для свойства `id_ЯндексКит` используется внутренний UUID **варианта** КИТ. Запись выполняется по двум измерениям регистра, «Объект» и «Свойство». После записи обработка проверяет значение и наименование характеристики до фиксации транзакции. Успех последнего теста в рабочей базе требует подтверждения журналом.

## История и воспроизводимость

Пять исходных сборок 1.84.0–1.84.4 импортированы последовательными коммитами. Это восстановленная история по файлам EPF. Даты коммитов отражают импорт. Три литерала с рабочими ключами заменены в исходниках локальными обозначениями. Исполняемая EPF с ключами распространяется отдельно. Инструмент экспорта извлекает данные для анализа, сборку EPF он не выполняет.
